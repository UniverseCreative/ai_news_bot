Microsoft Open-Sources Agensh: A Multi-Agent Harness for 1,024 Agents

📅 2026-10-25 12:22 ⏱️ زمان مطالعه: حدود ۲ دقیقه

Microsoft Research Agensh را به عنوان یک چارچوب غیرمتمرکز برای تیم‌های بزرگ برنامه‌نویسی متن باز کرده است. چارچوب چندعامله Agensh به حذف هماهنگ‌کننده مرکزی می‌پردازد که اکثر چارچوب‌های عامل به آن وابسته هستند. هر عامل وظیفه فرعی خود را انتخاب می‌کند، یافته‌ها را به اشتراک می‌گذارد و کد را به یک مخزن مشترک Git ادغام می‌کند. در ProgramBench، تیم این تنظیم را از ۱ عامل به ۱,۰۲۴ عامل گسترش داد.

Agensh یک چارچوب چندعاملی از Microsoft Research است که بسیاری از عوامل LLM را بدون یک عامل اصلی هماهنگ می‌کند.

مسئله هدف، سقف هماهنگ‌کننده است. در طراحی‌های هماهنگ‌کننده-کارگر، یک عامل اصلی برنامه‌ریزی، تخصیص و ادغام تمام کارها را انجام می‌دهد. مقاله پژوهشی به تیم‌های عامل Claude Code، زیرعوامل Codex، ناوگان Copilot و Kimi Agent Swarm به عنوان مثال‌هایی اشاره می‌کند. Agensh اجازه می‌دهد کارگران خود آن هماهنگی را انجام دهند.

هر کارگر یک حلقه ۵ مرحله‌ای یکسان را به‌صورت هم‌زمان و ناهم‌زمان اجرا می‌کند:

سه سرویس کارگران را متصل می‌کند. Gitea فضای کار مشترک را با شاخه‌ها، درخواست‌های ادغام و تعارضات ادغام میزبانی می‌کند. Mattermost یک کانال تیمی به علاوه پیام‌های مستقیم برای برخوردهای فوری را ارائه می‌دهد. یک تابلو زمینه مشترک، که از DeLM اقتباس شده، یادداشت‌های تایپ‌ شده را ذخیره می‌کند: OBSERVED، FACT، FAIL، CLAIM و PATCH_SUMMARY.

این حلقه در پرامپت زندگی می‌کند، نه در کد زمان اجرا. هر کارگر همان پرامپت را به جز شناسه خود دریافت می‌کند. Agensh بر روی یک چارچوب یک‌عامله نشسته است. آزمایش‌ها از GitHub Copilot CLI استفاده کردند. مقاله پژوهشی بیان می‌کند که آداپتورهای نازک می‌توانند سایر چارچوب‌ها را متصل کنند، مانند Claude Code.

تیم Microsoft سخت‌ترین وظایف ProgramBench را آزمایش کرد: FFmpeg، gromacs، pandoc، PHP-src و ctags. عوامل هر برنامه را از رفتار مشاهده شده آن بازسازی می‌کنند. آنها به‌صورت آفلاین کار می‌کنند و در عرض ۶ ساعت انجام می‌دهند. مخزن‌های مرجع از ۲,۷۶۷ فایل (pandoc) تا ۲۶,۲۶۶ فایل (PHP-src) متغیر است.

با GPT-5.6-sol در تلاش بالا برای استدلال، میانگین نرخ قبولی نهایی به شکل زیر تغییر کرد:

این یک افزایش ۹.۴۷ امتیازی، حدود ۴۹٪ نسبت به قبل است. تنها در مورد pandoc، امتیازها به ترتیب ۳۳.۸۹٪ (۱)، ۴۱.۷۵٪ (۸)، ۴۳.۱۱٪ (۳۲)، ۵۰.۹۴٪ (۱۲۸) و ۵۵.۰۶٪ (۱,۰۲۴) بود.

سرعت نیز بهبود یافته است: در pandoc، ۱۲۸ عامل در چک‌پوینت ۳۰ دقیقه‌ای ۳۰٪ قبولی داشتند. عوامل ۳۲ و ۸ به ترتیب به ۶۰ و ۹۰ دقیقه نیاز داشتند.

README یک مدل جدیدتر را اضافه می‌کند. با GPT-6.1-sol، pandoc از ۵۶.۱۹٪ (۱ عامل) به ۷۹.۵۹٪ (۳۲ عامل) افزایش یافته است. این یک افزایش ۴۱.۶۴٪ نسبی است. این ارقام GPT-6.1-sol در مقاله v1 ذکر نشده‌اند.

انتشار شامل یک تیم Docker Compose تک‌گانه و یک پایه‌ خطی عامل می‌باشد. هر دو از نشست‌های بومی Copilot ACP استفاده می‌کنند. شما به Linux با Docker Engine، Compose v2، systemd، cgroup v2 و Python 3.11+ نیاز دارید. تنظیمات پیش‌فرض شامل ۸ کارگر، ۶ ساعت برای هر وظیفه و gpt-5.6-sol با تلاش بالا می‌باشد. همچنین به ProgramBench (نسخه v1.2.5 تأیید شده) و توکن API مدل نیاز دارید. مراحل کامل در راهنمای بازتولید موجود است.
