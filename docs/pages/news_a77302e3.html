OpenAI Introduces Pando: A Git Backend That Cuts Median Push Latency ~80%

📅 2026-11-03 14:54 ⏱️ زمان مطالعه: حدود ۲ دقیقه

OpenAI از Pando رونمایی کرده است، یک بک‌اند جدید Git که اکنون تمامی توسعه‌ها را در مونو ریپوی خود پشتیبانی می‌کند. بک‌اند Git Pando از مشتری و پروتکل استاندارد Git حفظ شده است. مهندسان و مأموران Codex همچنان به‌صورت قبل از دستورات git push و git fetch استفاده می‌کنند. تنها سرور تغییر کرده است. تیم OpenAI گزارش می‌دهد که تأخیر میانه push تقریباً 80% کاهش یافته است. Pando اکنون تقریباً یک پتابایت داده Git در روز ارائه می‌دهد.

Pando یک سرور بک‌اند سازگار با Git از OpenAI است که امکان پشتیبانی از push و fetch همزمان را برای مونو ریپو فراهم می‌آورد. این سیستم در زبان Rust نوشته شده و ظرف 10 هفته به تولید رسیده است. یک مهندس هسته آن را طراحی کرده و تیم‌های مأمور Codex آن را پیاده‌سازی کرده‌اند. این سیستم از آوریل 2026 ترافیک تولیدی را ارائه کرده است.

Codex کارهای موازی را چند برابر کرده است. نمودار commit OpenAI نشان می‌دهد که تعداد commitهای موجود در master در مقایسه با Q1 2024، در Q3 2026 به میزان 1,378% افزایش یافته است. برآورد Q4 2026 تقریباً +2,442% است. هر push اکنون باعث ایجاد چندین fetch CI می‌شود. تا اواخر 2025، fetchها و pushها کند شده و ادغام‌ها ناکام مانده و در برخی موارد قابلیت اطمینان به پایین‌تر از 90% کاهش یافت. OpenAI نتیجه‌گیری کرد که گلوگاه در نحوه ارائه Git بوده و نه خود Git.

Pando دو فرضیه را که بیشتر سرورهای Git به‌عنوان الزامات در نظر می‌گیرند، کنار می‌گذارد:

1. سازگاری در سطح مخزن: سرورهای مرسوم هر به‌روزرسانی ref را در سطح کل مخزن مرتب می‌کنند، بنابراین pushهای نامربوط منتظر می‌مانند. Pando به‌جای آن از سازگاری علّی استفاده می‌کند. هر شاخه به‌طور مستقل سریال می‌شود و مشتریان تنها زمانی با هم تداخل دارند که همان ref را پشتیبانی کنند. با این تجارت، یک خواننده که چندین شاخه را مشاهده می‌کند، ممکن است آن‌ها را در زمان‌های متفاوت ببیند.

2. یک packfile منحصر به فرد برای هر مشتری: سرورهای استاندارد به‌ازای هر fetch یک pack جدید می‌سازند. Pando هر pack ارسال شده را به‌عنوان یک blob غیر قابل تغییر ذخیره می‌کند. هر "نسخه ref" به یک فروشگاه متادیتای مقیاس‌پذیر می‌رود. یک push به O(1) خواندن و نوشتن متادیتا نیاز دارد. یک fetch به O(log Δ) خواندن نیاز دارد، جایی که Δ فاصله بین نسخه‌های ref است.

با میلیون‌ها شاخه، یک تبلیغ کامل ref می‌تواند بیش از 100 MiB باشد. Pando تنها شاخه اصلی را به‌عنوان پایه‌ای برای pushهای شاخه‌های ویژگی جدید تبلیغ می‌کند. هر خواننده‌ای که تاریخچه شاخه اصلی را دارد، می‌تواند آن شاخه را از 1 pack ذخیره شده fetch کند. در مونو ریپوی OpenAI، میانه pack کمتر از 20 KiB بود.

Pando لینک‌های دانلود را از طریق packfile-uri، یک ویژگی موجود در پروتکل Git، ارائه می‌دهد. این سیستم یک pack خالی را به‌صورت آنلاین ارسال می‌کند. یک سرویس تحویل به نام Express packها را به‌صورت منطقه‌ای با استفاده از هشینگ سازگار ذخیره می‌کند و نرخ برخورد بالای 99% دارد.

هر push یک pack "L0" ایجاد می‌کند. کارگران پس‌زمینه packها را به پوشش‌های هندسی بزرگ‌تر گروه‌بندی می‌کنند، مشابه فشرده‌سازی LSM-tree. مونو ریپو در حال حاضر از پوشش‌های تا L4 استفاده می‌کند. پوشش‌ها به‌عنوان یک لیست پرش عمل می‌کنند، بنابراین انتخاب pack با زمان لگاریتمی انجام می‌شود.

تمام ارقام زیر به‌طور خودگزارش‌شده توسط OpenAI هستند.

OpenAI همچنین یک شبیه‌سازی 1,000 نویسنده را علیه طراحی‌های 3-phase-commit و write-ahead-log اجرا کرد. این شرکت این مدل‌های آموزشی را به‌عنوان مدل‌های آموزشی، نه معیارها، برچسب‌گذاری کرده است.

OpenAI یک مجموعه انطباق Git برای مأموران نوشته و آزمون‌های شبیه‌سازی قطعی را اضافه کرده است. مأمورانی که از GPT-6 Astra استفاده می‌کنند، مشخصات Lean و TLA+ را برای پیدا کردن باگ‌ها نوشته‌اند.

Pando ابتدا به‌عنوان یک پروکسی خوانده و نوشتن از طریق شبکه اجرا شد، بنابراین ترافیک بدون وقفه منتقل شد. OpenAI نسخه Git خود را به ماشین‌های توسعه‌دهنده و اپلیکیشن دسکتاپ ChatGPT ارسال می‌کند.

OpenAI مدیریت مشتریان را برای دانلودهای pack همزمان، قطع‌شده و از سرگرفته شده اصلاح کرده و ردیابی packfile-uri را اضافه کرده است. ساخت آن شامل ایندکس‌بندی pack به‌صورت موازی و "داشتن‌های صریح" است. چندین اصلاح به‌صورت upstream وجود دارد. باقی‌مانده در یک ردیاب اصلاحات عمومی قرار دارند.
