NVIDIA Releases Auto Ontology: An Open Semantic Layer That Grounds AI Agent SQL

📅 2026-11-02 16:52 ⏱️ زمان مطالعه: حدود ۲ دقیقه

NVIDIA کتابخانه‌ای به نام Auto Ontology را تحت مجوز Apache 2.0 منتشر کرده است. NVIDIA Auto Ontology یک چارچوب لایه معنایی است که لایه‌ای از زمینه را از متاداده‌های سازمانی می‌سازد. عوامل (Agents) از این لایه برای نوشتن SQL بر اساس تعاریف تجاری معتبر استفاده می‌کنند. این Repository مسئله را به‌روشنی بیان می‌کند: پاسخ سریع به درآمد در صورتی که شماره نادرست باشد، ارزشی ندارد.

این لایه زمینه‌ای بین یک عامل و انبار داده‌ها قرار دارد. این لایه به عامل می‌گوید که داده‌ها کجا قرار دارند و هر فیلد چه معنی‌ای دارد. همچنین تعیین می‌کند که آیا باید از یک فیلد استفاده کرد، چگونه از آن استفاده شود و منبع آن کجا است.

صفحه توسعه‌دهندگان NVIDIA خروجی را به عنوان یک انتزاع اولیه چارچوب‌بندی می‌کند. کارشناسان تجاری هنوز آن را آزمایش، تصحیح و تأیید می‌کنند.

این پشته دارای ۴ سرویس اصلی است. یک رابط کاربری وب با استفاده از Next.js 16 و احراز هویت روی پورت ۳۰۰۰ مدیریت می‌شود. یک backend مبتنی بر FastAPI با LangChain چت، NL-to-SQL و API‌های کاتالوگ را روی پورت ۳۰۰۱ اجرا می‌کند. یک کارگر ورود داده‌ها (ingestion worker) نگاشت‌ها را روی پورت ۳۰۰۲ می‌نویسد. پایگاه داده Postgres با pgvector کاتالوگ، انتزاع و وکتورها را ذخیره می‌کند.

پایگاه‌های داده منبع می‌توانند Databricks، Postgres، Snowflake یا DuckDB باشند. مدل‌ها از طریق "سه‌گانه‌های" محیطی شامل Endpoint، Key و مدل تنظیم می‌شوند. نقش‌های جداگانه‌ای برای نتیجه‌گیری، عدم نتیجه‌گیری، نگاشت و رتبه‌بندی مجدد وجود دارد. هر Endpoint سازگار با OpenAI کار می‌کند.

اسناد سرور MCP به شرح ۹ ابزار فقط خواندنی می‌پردازد. ابزار ask_question پاسخ، SQL و ردیف‌ها را به عنوان فیلدهای جداگانه باز می‌گرداند. نتایج حداکثر به ۱۰۰ ردیف محدود می‌شود. ابزار check_readiness تأیید می‌کند که لایه معنایی کامپایل‌شده و یک اتصال پایگاه داده زنده وجود دارد.

هیچ ابزاری برای مرور طرحواره‌های خام وجود ندارد. NVIDIA به‌طور عمد انتخاب کرده است که عوامل از طریق لایه معنایی به داده‌ها دسترسی پیدا کنند. مشخصات OpenAPI زیرساخت ۸۷ عملیات را منتشر می‌کند. ورود به سیستم از طریق OAuth انجام می‌شود و هر تماس شامل مجوزهای کاربر ورود کرده است.

NVIDIA یک هارنس جداگانه به نام auto-ontology-eval ارائه می‌دهد. این هارنس دو بازو درNeMo Gym اجرا می‌کند: یک کنترل فقط طرحواره LLM و یک عامل مبتنی بر انتزاع. نمره‌دهی بر اساس تطابق اجرای قطعی است و قاضی LLM وجود ندارد.

مجموعه داده‌های تجمیع‌شده شامل BIRDDev (۱,۵۳۴ سوال، ۱۱ پایگاه داده) و Mini-Dev (۵۰۰ سوال) است. FDABench-Lite به ۱۶۹ سوال اضافه می‌کند و BEAVER به یک نمونه ۱۰۰ سوالی پیش‌فرض می‌رسد.

مخزن هارنس دو محدودیت اضافه می‌کند. نمونه‌های اختیاری few-shot و لنگرهای مقداری فقط به بازوی انتزاع می‌روند. دلتای اندازه‌گیری‌شده با آن‌ها، آن ورودی‌ها را در بر می‌گیرد و نه فقط حقیقت‌گذاری. پیکربندی آزمایش‌شده آن نیز هر دو بازو را از طریق مدل Claude در دروازه استنتاج NVIDIA هدایت می‌کند.

راه‌اندازی محلی با دستور docker compose up -d --build پس از پر کردن .env انجام می‌شود. کاربران Kubernetes یک چارت Helm و یک راهنمای DEPLOYMENT.md دریافت می‌کنند. تیم NVIDIA همچنین backend را به عنوان یک کانتینر NGC منتشر می‌کند. یک کلید API از NVIDIA با آدرس build.nvidia.com مدل‌های پیش‌فرض را پوشش می‌دهد.
