Meet Anthropic’s sandbox-runtime: OS-Level Sandboxing for AI Agents, No Containers

📅 2026-10-24 11:53 ⏱️ زمان مطالعه: حدود ۲ دقیقه

در این مقاله، به بررسی ابزار متن‌باز و جدیداً محبوب Anthropic’s sandbox-runtime (srt) خواهیم پرداخت، که یک محیط ایزوله در سطح سیستم‌عامل است و پشت ابزار bash ایزوله شده Claude Code قرار دارد. Anthropic sandbox-runtime دسترسی به فایل‌ها و نقاط میزبان را برای یک فرآیند محدود می‌کند. این کار بدون راه‌اندازی یک کانتینر انجام می‌شود و همچنین به Claude Code وابسته نیست. شما می‌توانید عوامل خود، سرورهای محلی MCP و برنامه‌های ساده خط فرمان را درون آن اجرا کنید.

Anthropic sandbox-runtime ابزاری متن‌باز است که هر فرآیند را در محدودیت‌های سیستم‌فایل و شبکه قرار می‌دهد. شما آن را با دستورnpm install -g @anthropic-ai/sandbox-runtime نصب می‌کنید و سپس یک دستور را با srt پیشوند می‌زنید. این ابزار به عنوان یک CLI و همچنین به عنوان یک کتابخانه TypeScript کار می‌کند.

srt از اصول جداکننده خود هر سیستم‌عامل استفاده می‌کند. محدودیت‌های آن تمام درخت فرآیند را پوشش می‌دهد، از جمله اسکریپت‌ها و زیر‌فرآیندها.

ترافیک فقط از طریق پروکسی‌های HTTP و SOCKS5 که روی میزبان اجرا می‌شوند، خارج می‌شود. در Linux، این پروکسی‌ها پشت سوکت‌های Unix قرار دارند که به محیط ایزوله متصل شده‌اند. در macOS، پروفایل Seatbelt تنها به یک پورت localhost اجازه می‌دهد. سپس این پروکسی‌ها فهرست مجاز و ممنوع دامنه شما را اعمال می‌کنند.

تیم Anthropic معتقد است که ۱ مرز بدون دیگری نادانستنی است. بدون ایزوله‌سازی شبکه، یک عامل که به آن تزریق فرمان شده، می‌تواند کلیدهای SSH را خارج کند. بدون ایزوله‌سازی سیستم‌فایل، ممکن است از محیط ایزوله خارج شود و به شبکه دسترسی پیدا کند.

پیکربندی پیش‌فرض srt این منطق را دنبال می‌کند. خواندن داده‌ها در هر جایی مجاز است مگر اینکه ممنوع شود. نوشتن داده‌ها در هر جایی ممنوع است مگر اینکه مجاز باشد. دسترسی به شبکه ممنوع است مگر اینکه یک دامنه در فهرست مجاز قرار داشته باشد.

برای عامل خود، کتابخانه SandboxManager را معرفی می‌کند. برای شروع پروکسی‌ها، تابع initialize(config) را فراخوانی کنید. سپس wrapWithSandbox() یک رشته دستور ایزوله شده برمی‌گرداند که می‌توانید آن را اجرا کنید.

Anthropic گزارش می‌دهد که ایزوله‌سازی، درخواست‌های مجوز را در استفاده داخلی از Claude Code به میزان ۸۴٪ کاهش داده است. این یک عدد خود گزارشی است و نه یک معیار خارجی. هدف کاهش خستگی از تایید است. توسعه‌دهندگانی که تمام روز روی "تایید" کلیک می‌کنند، دیگر آنچه را که تایید می‌کنند، نمی‌خوانند. یک مرز ثابت به عامل اجازه می‌دهد که درون آن به طور آزاد کار کند و تنها در لبه درخواست کند.

عوامل کدنویس بیشتر از ویرایش فایل‌ها کار می‌کنند. آن‌ها وابستگی‌ها را نصب می‌کنند، مستندات را کشیده و API‌ها را فراخوانی می‌کنند. اگر فهرست مجاز بسیار سختگیرانه باشد،npm install شکست می‌خورد. اگر بسیار سست باشد، محیط ایزوله به سختی محافظت می‌کند. srt چندین گزینه برای ایجاد این تعادل می‌آورد:
